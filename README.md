# Сайт «ДЕЗЦЕНТР SANITAR» (Самара)

Сайт с админкой для клиента. PHP 8.1+ без сторонних библиотек и без базы данных. Контент лежит в `data/*.json`, сборщик (`app/lib`) делает из него готовые HTML-страницы, админка (`app/admin`) правит JSON и сразу пересобирает сайт. Посетитель получает обычный статический HTML: быстро, хорошо для поисковиков, сайт работает, даже если админка сломается.

До сентября 2026 сайт собирался на Node (`_src/`). PHP-сборщик написан как точная копия: все 16 страниц, `styles.css`, `sitemap.xml` и `robots.txt` совпали со старым выводом побайтно, в том числе в режиме превью. Старый сборщик удалён, чтобы не было двух источников правды.

## 1. Что где лежит

| Путь | Что это |
|---|---|
| `data/*.json` | **Единственный источник правды**: тексты страниц (`site.json`), услуги (`services/*.json`), компания и контакты, цены, отзывы, видео, фото, фоны первых экранов (`structure.json`). Правится в админке |
| `data/hero.json` | Размеры готовых фонов из `public/images/hero` — описание кода, админка его не меняет |
| `app/lib` | Сборщик: `render.php` (шапка, подвал, формы, разметка текстов, оболочка), `pages.php` (страницы), `build.php` (сборка, CSS), `icons.php` |
| `app/css` | Исходники стилей: критическая часть встраивается в страницу, остальное собирается в `styles.css` |
| `app/admin` | Админка: `schema.php` (какие поля есть — добавить поле = одна строка), `content.php` (проверка и сохранение), `ops.php` (услуги, фото, корзина, история), `ui/` (интерфейс) |
| `app/lead.php`, `app/lead-deliver.php` | Приём заявок: журнал и почта |
| `app/bin` | `build.php` — сборка, `admin-setup.php` — вход в админку, `deploy.php` — заливка по FTP |
| `public/` | Статика: картинки, шрифты, видео, `script.js`, `.htaccess`, заглушки `lead.php` и `admin/index.php` |
| `dist/` | Собранный сайт (в git не хранится) |
| `storage/` | Пароль админки, сессии, заявки, история правок, корзина (в git не хранится, на сервер не заливается) |
| `tools/` | Подготовка медиа на Node: фоны первого экрана (`make-art.cjs`, Real-ESRGAN), сжатие видео, логотип |

## 2. Работа на своём компьютере

```bash
php app/bin/build.php                      # собрать сайт в dist/
php -S 127.0.0.1:8081 app/dev-router.php   # сайт http://127.0.0.1:8081, админка /admin/
php app/bin/admin-setup.php <пароль>       # создать вход в админку (один раз)
```

Локальные настройки — `app/config.local.php` (в git не хранится): `site_url` `http://127.0.0.1:8081`, `admin_local_no_gate` `true` (на localhost без секретного адреса). По умолчанию — `app/config.php`.

Пока домен не выбран, `site_url` пуст и в ссылках для поисковиков стоит плейсхолдер `{{ДОМЕН}}`. Пустые реквизиты на сайте видны жёлтыми пометками `{{ИМЯ}}`; сборка печатает их список.

## 3. Админка

Адрес входа: `https://домен/admin/<секретное-слово>`, затем пароль. Без секретного адреса любой адрес `/admin/...` отвечает обычной страницей 404.

Что умеет:
- **Страницы**: главная, «Цены», «Документы», «Отзывы», «Контакты» — все тексты, фон первого экрана, заголовок и описание для поисковиков.
- **Услуги**: правка всех блоков страницы. Можно добавить новую (создаётся скрытой, пока не заполнена), скопировать, скрыть, поменять порядок, удалить в корзину. Галочка «Показывать в меню» — основные направления (меню, карточки на главной, подвал); страницы вредителей — без неё, с разделом-родителем. Ссылки на скрытую или удалённую услугу со всего сайта убираются сами.
- **Цены**: цена квартиры и сотки подставляются во все тексты вместо `@@PRICE_FROM@@` и `@@PRICE_LAND@@`; таблица цен одна на весь сайт.
- **Компания и контакты**: телефоны (ссылка `tel:` считается сама), почта, мессенджеры, адрес и точка на карте, режим работы, города, рейтинг, реквизиты, дата редакции политики, Метрика.
- **Отзывы**, **Общие блоки** (шаги работы, методы, текст подвала, фоны политики и 404), **Видео** (подписи, разделы, порядок).
- **Фото**: загрузка перетаскиванием (браузер уменьшает крупные фото, сервер делает WebP 1280 и 640 px в `public/images/foto`), подписи, папки, порядок, удаление в корзину. Фото, которое где-то используется, удалить нельзя — админка скажет где.
- **Заявки**, **История правок** (любую прежнюю версию можно вернуть), **Корзина**, **Настройки** (куда слать заявки, смена пароля).

**Разметка в длинных текстах** (тексты услуг, ответы на вопросы): пустая строка — новый абзац; `## Заголовок` (можно `{#якорь}` в конце) — подзаголовок; строки с `- ` — список; `**жирный**`; `[текст](/адрес/)` — ссылка; `@@PHONE1@@`, `@@PHONE2@@` — телефон ссылкой. Во всех текстах работают `@@PRICE_FROM@@`, `@@PRICE_LAND@@`, `@@RATING@@`, `@@REVIEWS@@`, `@@TEL1@@`, `@@TEL2@@`.

На самом сайте никаких кнопок админки нет: править можно только через адрес входа в админку.

Если сохранение ломает сборку (например, выбран несуществующий отзыв), файлы возвращаются как были и админка показывает ошибку — сайт не ломается.

## 4. Заявки

Форма отправляет заявку на `/lead.php` (заглушка в корне сайта, обработчик — `app/lead.php`). Сервер:

- проверяет согласие, имя и телефон (11 цифр) независимо от браузера;
- отсекает ботов: скрытое поле-ловушка и время заполнения меньше 3 секунд;
- **сначала записывает заявку в журнал** (`storage/leads`, видно в админке), потом отвечает посетителю, и только после ответа шлёт письмо;
- больше 30 заявок в час с одного адреса — заявки пишутся в журнал, но уведомления не шлются.

Куда слать — в админке → «Настройки»: почты для заявок и отправитель. В Telegram заявки не отправляются — только на почту (решение заказчика). Если почта не указана, заявки идут на e-mail из «Компания и контакты» (сейчас olimp@samara-7.ru). Кнопка «Отправить проверочную заявку» шлёт тестовое сообщение.

**Отличия от прежнего `api/send.php`:** SMTP больше не поддерживается — письма уходят через `mail()` хостинга (на части хостингов такие письма попадают в спам; отправитель лучше на домене сайта). Лимит тоже другой: раньше шестая заявка за час с одного IP отклонялась, теперь все заявки сохраняются, а после 30 в час перестают приходить уведомления.

## 5. Хостинг (Beget и т.п.)

Раскладка на сервере:

```
~/сайт/app          — ядро (папка app)
~/сайт/data         — данные: единственный источник правды
~/сайт/storage      — пароль, сессии, заявки, история, корзина (создаётся сама)
~/сайт/public_html  — корень сайта: статика из public/ + собранные страницы
```

1. `app/deploy.local.php` — доступ по FTP (пример — `app/deploy.example.php`); `app/config.server.php` — настройки сервера (`site_url`, `public_dir` и `out_dir` = `ROOT_DIR . '/public_html'`, `deploy_key` не короче 24 символов — тот же в `deploy.local.php`).
2. `php app/bin/deploy.php init <пароль>` — первая установка на пустой сервер: код, данные, фото, настройки, вход. Печатает секретный адрес входа.
3. Дальше: `php app/bin/deploy.php push` — залить код (никогда не трогает `data/`, загруженные фото и `storage/`) и пересобрать сайт на сервере; `php app/bin/deploy.php pull` — забрать сюда то, что клиент поменял в админке. **Перед правкой шаблонов — сначала `pull`.**
4. Подключить SSL и раскомментировать https-редирект в `public/.htaccess` (раньше — будет петля).
5. После переезда выключить превью на GitHub Pages, чтобы не было второй, устаревшей копии.

Проверить на реальном хостинге (локально этого не видно): версия PHP у веб-сервера ≥ 8.1, применился ли `.user.ini` (загрузка фото до 32 МБ), работает ли `mail()` с отправителем на домене, доступен ли `api.telegram.org`, доходит ли `/admin/…` до `admin/index.php`, разрешён ли `Options -Indexes`.

## 6. Фоны, видео, документы

- Фоны первого экрана: `public/images/hero/*.webp` (компьютер, `-1200`, `-m` для телефона). Делает `tools/make-art.cjs` из материалов клиента с увеличением через Real-ESRGAN (`REALESRGAN=D:/tmp/realesrgan/realesrgan-ncnn-vulkan.exe node tools/make-art.cjs <имя>`, нужны `sharp` и `ffmpeg-static`). Скрипт обновляет `data/hero.json`. Какой фон на какой странице — в админке.
- Видео: `public/video/work-NN.mp4` + постер `work-NN.webp`; сжатие — `tools/media.js`. Новый ролик добавляет разработчик, подписи и порядок — в админке.
- Документы: сканы в «Фото» → папка «Документы», список — в админке, раздел «Документы».

## 7. Превью на GitHub Pages

Ветка `gh-pages` ведётся из вложенного репозитория в `dist-pages/` (в `.gitignore`). Адрес: `https://mihailburmasov.github.io/sanitar-samara/`, с `noindex`.

```bash
MSYS_NO_PATHCONV=1 SITE_URL=https://mihailburmasov.github.io SITE_BASE=/sanitar-samara NOINDEX=1 OUT_DIR=D:/Claude/Projects/Sanitar/dist-pages php app/bin/build.php
cd dist-pages && git add -A && git commit -m "..." && git push origin gh-pages
```

`MSYS_NO_PATHCONV=1` обязателен в Git Bash, иначе `/sanitar-samara` превращается в путь Windows (поэтому и `OUT_DIR` — полным путём). Сборка не трогает `.git` внутри `dist-pages`. На GitHub Pages нет PHP: форма там показывает ошибку с телефоном, админки нет.

## 9. Что проверено

- **Перенос сборщика**: все файлы старого и нового вывода совпали побайтно (обычная сборка и превью в подпапке).
- **Админка**: каждый раздел и каждую услугу загрузили и сохранили без изменений — «Изменений нет» и чистый `git status data`. Функциональный тест (45 проверок): экранирование, выделение в заголовке, откат по истории, отказ на неверное значение без поломки сайта, подстановка цен, новая услуга (скрыта → опубликована, разметка текста, хлебные крошки, выбор в форме, не в меню, в sitemap), копия, порядок, удаление с чисткой ссылок и возвратом из корзины, запрет удалить раздел с дочерними страницами, загрузка фото → в текст услуги → запрет удаления занятого → удаление и возврат, смена телефона, заявка, отказ плохой заявке, 401 без входа.
- **В браузере** (headless Chrome): скриншоты админки на 1360 и 390 px без горизонтальной прокрутки и без ошибок JavaScript; форма на сайте отправляется, заявка видна в админке; кнопка «Редактировать» есть только у вошедшего.
- **Заливка по FTP** (эмуляция хостинга: локальный FTP и PHP-сервер как Apache): `init` на пустой сервер → вход по секретному адресу, правка текста и загрузка фото «клиентом» → `push` кода (правка дошла, правки клиента целы) → `pull` забрал ровно изменённое (`site.json`, `photos.json`, два файла фото). Повторный `init` отказывает; `pull` с неверной папкой и при пропаже больше 5 файлов на сервере останавливается, ничего не удаляя.
- **Прежние замеры** (вывод страниц не изменился): Lighthouse мобильный — главная 94–96 / 100 / 100 / 100, внутренние 98 / 100 / 100 / 100; адаптив 360 / 768 / 1440 px; один `h1`, `alt` и размеры у картинок, валидный JSON-LD, контраст ≥ 4,5:1.

Не проверялось: работа на реальном хостинге (почта через `mail()`, `.user.ini`, настоящий FTP хостинга), Safari/iOS и Firefox.
